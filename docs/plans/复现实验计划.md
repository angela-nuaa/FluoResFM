# FluoResFM 补充实验与复现计划

> 状态：进行中（计划建立于 2026-07-28）；当前执行状态与协议阻塞见[当前进度总览](../progress/当前进度总览.md)。
> 总目标：在可获得公开资源的范围内，尽量接近论文协议复现 FluoResFM；在无法满足论文协议时，明确标注为近似复现或探索性补充实验。

## 1. 不可变原则

- GPU 只用于模型推理和训练；所有指标、统计检验、作图和结果汇总固定在本地执行。
- 原始数据、下载压缩包、预训练权重、派生数据、预测 TIFF、日志和实验结果只保存在被 Git 忽略的目录中，不得提交 Git。
- 每次运行使用新的目录，禁止覆盖旧运行；每个运行必须包含 `manifest.json` 与 `run.md`。
- `manifest.json` 至少记录根仓库、两个子模块的提交 ID，命令、环境、硬件、随机种子、输入文件清单及 SHA-256。
- 论文协议复现、近似复现、提示敏感性实验必须分目录、分表格、分结论报告，不能混合汇总。

## 2. 证据等级与命名

| 等级 | 定义 | 可使用表述 |
| --- | --- | --- |
| P0：论文协议复现 | 使用作者对应测试划分、逐文件元数据、规范文本、权重和评估逻辑。 | “按可核验的论文协议复现”。 |
| P1：近似复现 | 使用公开替代数据或部分协议要素；所有偏离均已记录。 | “近似论文设置的复现”。 |
| P2：补充实验 | 为检验提示、稳健性或形态保留而设计，非论文主实验。 | “本地补充实验”或“提示敏感性实验”。 |

当前已有 MT 与 CCP 的字段删除/错误先验结果均为 P2；不得改称 P0 或 P1。

## 4. 分阶段工作清单

### 阶段 A：复现基础设施与协议核验

- [x] 固定根仓库及 `repos/fluoresfm`、`repos/napari-fluoresfm` 的提交 ID，并写入新的运行记录。
- [x] 为三份规范推理脚本补齐版本、命令、运行时、关键资产哈希和 `run.md` 记录。
- [ ] 获取并归档来源、许可、下载日期和 SHA-256：预训练权重、BiomedCLIP、数据压缩包。
- [x] 核验上游 `dataset_test-v2.xlsx` 中 BioTISR 外部 SR 的 12 个标准数据集 ID、任务和文本字段。
- [ ] 获取作者已转换外部测试集或可核验的 RawSIM→WF 处理流程；随后运行 `audit_biotisr_protocol.py` 核验逐文件输入、GT 与元数据映射。
- [ ] 对每个候选样本建立本地、未跟踪的配对清单：`input ↔ reference ↔ metadata row`。

**验收标准：** 不存在仅靠文件尺寸或目录名推断任务/元数据的样本；每个纳入定量评估的图像均能追溯到原始元数据行。

### 阶段 B：预训练零样本近似/协议复现

- [ ] 优先运行外部 BioTISR 的 SR 保留子集：CCP、F-actin、lysosome、MT。
- [ ] 在元数据允许后扩展至去噪、去卷积及其他外部数据集。
- [ ] 用上游 `3_0_test_it2i.py` 的推理约定生成预测，保存规范文本与逐图映射。
- [ ] 每个数据集先完成一个小型 smoke test，再完整运行；预测只在 GPU 生成。

**验收标准：** 每个数据集有完整预测数、输入数和参考图数的一致性检查；失败或缺失文件显式列出，不静默跳过。

### 阶段 C：固定本地评估校准

- [ ] 固定本地评估环境与依赖版本。
- [ ] 对同一批预测逐图复算 PSNR、SSIM、MS-SSIM、ZNCC、NRMSE、RSE/RSP。
- [ ] 与上游 `4_0_result_evaluate.py` 的实现核对百分位归一化、裁剪、尺度、图像配对和聚合规则。
- [ ] 在校准通过前，不报告与论文数值的直接比较。

**验收标准：** 逐图指标差异有可解释来源；若不能数值一致，记录偏差并将结果标注为 P1，而非 P0。

### 阶段 D：对照、统计与报告

- [ ] 报告原始输入与 FluoResFM；仅在有可获得、可比权重和设置时加入无文本变体及其他基线。
- [ ] 保留逐图指标、每数据集均值/标准差、样本数和失败数。
- [ ] 统计检验预先定义为按图配对；多重比较校正、双/单侧假设和排除规则写入运行记录。
- [ ] 按任务与数据集分别报告，不将异质数据直接合为单一总分。

**验收标准：** 每张图、每项指标、每项统计结论均可从 manifest、预测和本地评估输出追溯。

### 阶段 E：补充可复现实验

- [ ] 在已核验的保留集上重做单字段删除、语义等价改写和错误先验实验。
- [ ] 将“字段存在性”“措辞变化”“真实元数据变化”拆成独立实验。
- [ ] 加入形态学验证：MT 纤维长度、CCP 尺寸，必要时扩展 ER 网络指标。
- [ ] 仅当存在独立标注与明确协议时，开展分割下游验证。

**验收标准：** 像素指标、形态学指标和定性图共同报告；无参考或无标注结果不作为真实性证明。

### 阶段 F：微调复现（后续）

- [ ] 使用配对样本，按视野/样本隔离训练、验证与测试。
- [ ] 复现仅更新 U-Net 骨干第一层和最后一层卷积层的微调设置。
- [ ] 固定 1、少量、更多样本的样本量序列与随机种子。
- [ ] 与零样本推理、可比基线一起在独立保留集上本地评估。

**验收标准：** 微调样本与评估样本无重叠，并且每个样本量都有完整训练配置和保留集结果。

## 5. 目录与运行规范

```text
data/                         原始及派生数据（Git 忽略）
example/                      上游下载资源（Git 忽略）
experiments/<protocol>/<id>/  预测、指标、manifest、run.md（Git 忽略）
docs/                         计划、方法说明、可审阅汇总（Git 跟踪）
scripts/                      可复现的推理编排、评估和统计脚本（Git 跟踪）
```

运行编号建议使用：`YYYYMMDD_<protocol>_<dataset-or-scope>_<short-note>`。例如：`20260728_p1_biotisr_mt_sr_zeroshot`。

## 6. 每轮运行前检查

- [ ] 新运行目录不存在，且未启用覆盖选项。
- [ ] 输入、参考图、元数据三者文件名集合一致。
- [ ] 权重、数据与子模块提交已记录哈希。
- [ ] GPU 命令只生成预测；本地命令单独生成指标、统计和图表。
- [ ] 运行结束后确认 Git 状态中没有数据、权重或实验产物待提交。

## 8. 局限与待验证问题

- 上游 README 说明完整处理数据可按需向作者获取；当前捆绑示例不足以单独支撑严格论文复现。
